# 委派纪律拆两处：插件管机制，用户目录管路径与动机

## 背景与决定

委派规则同时存在于两处系统提示词里：用户全局 `~/.dsh/AGENTS.md` 的「## 委派」节（21 行中文），以及 model-pack 注入的 `model-pack.delegation` 段（英文）。两者在「独立任务走 `subagent_tier`、fork 只留给上下文相关任务、独立任务一次派出、收尾逐项验收」上逐句重复。

宿主实测（0.2.2-rc.1，`@deepseek-ai/dsh-agent-instructions`）：子代理**不复用**父侧提示词串，自己在 `lib/types/files.js:205` 的 `discoverBaselineInstructionFiles` 里重读工作区与全局 `AGENTS.md`；而 `model-pack.delegation` 段只在父会话的 `agent/created` 注入。同一段文字对两个读者生效，因此不能简单合并。

决定按两个维度拆：**谁读得到**、**随什么变化**。

- 进段（父会话，且随工具是否存在而变化）：派不派的判据、按难度切轨道、四档线索、检查点要求、自足交付、收尾验收。
- 留在 AGENTS.md（子代理也读，且与项目目录约定绑定）：插件缺位时退回 `subagent_fork`、工作区一个档都没配时的兜底、检查点落盘路径 `./.tmp/subagent/`、并发投放的 PTC 写法、子代理中途失败读检查点。
- 删除：两处都有的重复四条。

段预算 350 → 400。spec §6.3 原写「工具描述 ≤400」实测只有 145，改成 ≤200 作护栏；合计上限 750 → 600。

## 考虑过的替代方案

### 整段搬进插件，AGENTS.md 全删

否掉：子代理读不到段。「每约 8 次工具调用追加检查点」是对子代理的动作要求，段里只有父代理视角的「给出检查点路径」；全删后只剩父代理每次在 `prompt` 里口头要求，漏写即无兜底。插件停用、`subagents` 服务缺失、或工作区没配档时，段整段不注入，模型手上一条委派规则都没有。

### 保持 350 上限，压缩现有句子腾位置

否掉：压缩要动 `Plan before delegating` 这类被测试锚定的句子，改动面从「追加三行」扩大到「重写句子 + 改三条断言」。而省下的约 40 token 没有对应的预算压力——工具描述实测 145，合计 545，离 750 很远。

### 在 AGENTS.md 保留「高档与主会话同模型」

否掉：档位路由是独立配置，tier4 与主会话未必同模型；这句会随配置过时，且与段里 `When unsure, take the higher tier` 读起来对立。选档规则只留一处。

## 后果

- 父会话 token 净省约 100/轮，**来自去重，不来自搬家**：段 +104 与 AGENTS.md 减项基本相抵。
- 子代理不再看到判据与回收（不需要），仍能看到检查点路径与失败处置。
- 段可被 `prompts.json` 覆盖，但改不了落盘路径——那是项目约定，不是插件知识。
- 400 是护栏不是目标：当前 372，余量留给措辞修订；档名可被用户改长，故工具描述留 200 的护栏。
