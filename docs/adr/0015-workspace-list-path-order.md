# 工作区页是全局视图：清单按路径排序，不跟当前目录

## 背景与决定

工作区页（四个包各一页）列的目录来自宿主会话列表。原来每条清单都按「当前会话所在目录置顶，其余按最近更新倒序」排：切一次会话，整页就重排一次；model-pack 还把清单第一项当作「当前目录」，用它回读绑定。

决定三条：

1. **清单按路径排序。** 比较键是归一化后的 cwd（去尾斜杠、反斜杠转正斜杠、Windows 转小写），用 `localeCompare(…, 'zh', { numeric: true, sensitivity: 'base' })`：大小写不敏感、数字按自然序、中文目录按拼音，平局用原始字符串兜底。四个包各写一份，与既有的 `normalizeCwd` 一样靠测试与护栏保持一致。
2. **不置顶。** 当前会话目录不再单独排第一；排序与哪个会话在前台无关。
3. **设置页是全局视图。** model-pack 的 `read` / `apply` 不带 cwd，不按任何目录求值；`currentCwd` 只剩 chip 与 composer 标签在用，按 `sessionId` 显式解析，找不到时退回最近更新的根会话，不读清单第一项。

截断保留原语义：mcp / plugin / skill 仍按最近使用挑前 30 条，只是挑完再按路径展示；model-pack 不截断，绑定表里残留的目录与会话目录合并后一起排序。

## 考虑过的替代方案

**保留置顶，其余按路径。** 否掉：设置页是一次性配置，不是「跟着我在哪个目录干活」的视图。置顶让第一行随会话切换而变，用户对着它找目录时要先找那行再往下读，路径序就被打断一次。

**只改展示层，清单仍按最近更新返回。** 否掉：四个包的工作区页都直接渲染清单，没有第二层；把排序放在渲染处等于把同一份比较逻辑抄进四页的渲染里，测试只能测到组件内部。

**不排序，改成可点表头。** 否掉：没人要求第二套交互；工作区页只需要一个稳定顺序。

**把比较逻辑抽成共享包。** 否掉：浏览器半边不能引服务端模块，四个 client 的单文件约定（[ADR 0002](./0002-keep-workspace-plugins-separate.md)、`check-panels` 护栏）比省下的十几行更值钱；`normalizeCwd` 已经在四份里逐字重复。

## 后果

- **清单顺序与当前会话解耦。** 切会话不再重排工作区页；同一批目录每次都排成同一个序。
- **chip 与 composer 标签不受影响。** 它们仍按会话解析目录，只是不再从清单第一项取。
- **设置页少一次按目录求值。** `state.binding` / `resolved` 在设置页的响应里恒为 null；这两项本来只有 chip 弹层与标签在读，各读各的视图。
- **`MAX_WORKSPACES` 的取舍与展示分成两步。** 先按最近使用截断、再按路径排序；反过来会让最近用过的目录被字典序更靠前的旧目录挤掉。
- **四包各多一条可回归的用例。** 排序、去重、截断、当前目录解析各有断言；改排序键时先改测试。

## 何时重新考虑

- 工作区页需要「最近使用」作为第二种视图（例如分组、筛选），届时排序键变成可切换的视图状态，而不是全局约定。
- 宿主提供工作区列表的原生接口（有序、带显示名），四包的会话列表拼装与排序就都该退役。
- 实际使用中出现「必须让当前目录一眼可见」的强诉求时，重开「置顶」的决定，但要把「置顶行随会话跳动」的代价重新量一次。
