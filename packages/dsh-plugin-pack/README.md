# @dreanzy/dsh-plugin-pack

按工作区停用插件。停用一个插件做两件事：把它注册的工具从模型可见的工具里摘掉，把它注入的提示词段从 system prompt 里剔掉。

[English](README.en.md) | **简体中文**

## 它解决什么问题

两个目的，通常同时成立：

1. **省 token**。插件的工具 schema 与提示词段每一轮都要重发。装得越多，固定开销越大，候选越多模型越容易选错。
2. **不让某个工作区用某个插件**。纯文档的仓库不需要执行器，前端的仓库不需要图像生成——能力留着就一直在候选里。

插件是**开关单位**：一个 npm 包要么整体可用，要么整体不可用。不提供「关插件但保留某个工具」——那需要一个反向开关，而底层只有收紧语义（见[已知边界](#已知边界)）。

## pack 与求值

```
绑定的 pack 项级  ??  绑定的 pack 组级  ??  default 项级  ??  default 组级  ??  默认开
```

前一环存在就不读后面的。pack 是一张具名的策略表，只含覆盖决定，不含成员清单。工作区只存一个绑定：绑到某个 pack，或什么都不绑（走 `default`）。`default` 是内置 pack，不可删除、不可改名，内容可编辑——它就是原来全局层的落点。

键不存在即「跟随」，`false` 是「明令关」，两者不是一回事。所以普通 pack 的每个开关是三态（开 / 关 / 跟随），而 `default` 只有两态：它是求值链的终点，没有上一层可跟。

工作区目录下不再产生任何状态文件。

## 安装

需要 DSH `0.2.x`（`0.2.0-rc.2` 及以上）。

**在 Web 界面安装**：设置 → 插件 → 添加插件 → 安装第三方插件，输入包名：

```
@dreanzy/dsh-plugin-pack
```

**命令行安装**：

```sh
dsh plugin --profile <profile> add @dreanzy/dsh-plugin-pack
```

装完重启 Host、刷新页面。

从源码安装（需要 pnpm 允许该包执行构建）：

```sh
dsh plugin --profile <profile> add "github:dreanzy/dsh-plg#<sha>&path:/packages/dsh-plugin-pack"
```

## 文件

| 路径 | 内容 |
| --- | --- |
| `$DSH_HOME/packs/plugin/packs.json` | pack 名册与 `ui` 段（`showChip`、`defaultTab`） |
| `$DSH_HOME/packs/plugin/groups.json` | 组定义与归属，跨工作区共享 |
| `$DSH_HOME/packs/plugin/workspaces.json` | 工作区 → pack 的绑定表，外加手动添加的路径 |
| `$DSH_HOME/packs/plugin/catalog.json` | 归属扫描的缓存（可删，删了重扫） |

三个策略文件各自独立事务：pack 的编辑压力都在 `packs.json`，组定义与绑定变动稀少，拆开是为了让每份文件都能单独原子写。删除一个 pack 后，绑定表里指向它的键会成为悬空引用，读侧按 `default` 求值，写侧顺手清掉。

旧路径（`$DSH_HOME/plugin-manager/` 与 `<cwd>/.dsh/plugin-manager.json`）的兼容读已移除：迁移完成后这些文件连同读取分支一起删掉了，现在只认上面三个文件。

## 面板

- **三页**：`分组 | 分包 | 工作区`，顺序固定，打开时落在 `ui.defaultTab`。切页只改当前页，不写盘；只有页首那组「打开设置时默认显示」的单选才改默认页。
- **一个开关只有一个入口**。开关属于 pack，只在「分包」页出现；「分组」页只做结构（新建、改名、删除、改归属），不放开关。普通 pack 的开关三态——开 / 关 / 跟随，跟随是独立的可点选项；`default` 只有两态，未记录即内置缺省（开）。
- **工作区页**只做绑定：每行一个 pack 下拉，未选即「默认」。绑定只影响该目录下**新开**的会话；策略在会话创建时求值，已经开着的会话不会换 pack。
- **分区**：官方 / 第三方，按包名的 npm 作用域自动切（`@deepseek-ai/` 是官方）。只用于展示，不参与求值，也不能当开关单位。分区标题可点开合。
- **排序**：插件行按「开 > 关 > 跟随（开）> 跟随（关）」分档，同档按包名；分组用同一套档位。顶部统计「已停用 N 个插件，约省 M token」，每次保存后按服务端返回的视图更新。
- **行内容**：完整包名（不去 `@scope/` 前缀——`@a/x` 与 `@b/x` 会撞名）、官方/第三方标签、`N 工具`、`N 段`、`≈M token`、开关。
- **搜索**：包名子串匹配，大小写不敏感。刻意不做模糊匹配：`dsh` 这类片段到处都是，模糊只会让结果更难认。搜索时分区强制展开。
- **受保护插件**：行标「受保护」。停用它要二次确认，确认框里列出包名。名单固定（读写工具、执行器、system-prompt、本插件自己），不由任何 pack 改写。
- **提交**：每个开关点击立即发一条 `apply`，没有本地草稿与撤销；批量动作（例如一次归组）合成一条请求。保存失败时显示错误并重新读取服务端状态。
- **分组与 pack 正交**：分组描述「哪些插件是一类」，pack 描述「这些插件对这些工作区是开是关」。组开关写在 pack 里，与项开关并列；「分组」页不改任何开关。
- **不显示 cwd**：工作区页按目录名认工作区，绑定表里的键是规范化后的路径。

### 探针

列表上方按顺序显示这些状态，任何一条都比开关先被看见：

| 条件 | 文案 |
| --- | --- |
| `support.restrict === false` | 当前宿主不支持工具限制，停用只影响提示词 |
| `support.promptFilter === false` | 当前宿主不支持提示词段过滤，停用只影响工具 |
| `pending === true` | 正在识别插件归属（首次约 1 秒，之后读缓存） |
| 识别不到任何官方插件 | 没识别到任何官方插件，归属扫描可能未定位到 app.asar；此时官方插件不会出现在列表里 |
| `stuck` 非空 | 列出关不掉的工具名（宿主按未知名字整批拒绝后已剔除） |
| `outOfScope` 非空 | 折叠列出「策略里有、目录里没有」的包名，保留不删 |
| 行的 `sectionKnown === false` | 提示词占用未知 |

## 写入语义

每次保存提交的是一组**意图**（`{ op: 'packItem' | 'packGroup', packId, name, value: boolean | null }`、`createPack` / `renamePack` / `deletePack`、`bind` / `addExtra` / `removeExtra`、分组的 `assign` / `createGroup` / `renameGroup` / `deleteGroup`、`showChip` / `defaultTab`），服务端在文件锁内读—改—写，不比对版本。命令幂等、可交换，写同一键即后点者赢，所以不存在 `stale-revision` 这类冲突。`null` 表示删掉这条键、回到跟随——写一个同值不等于跟随。

`bind` 自带 `cwd`，所以写入不依赖会话；`sessionId` 只决定 apply 返回哪一种视图。显式绑到 `default` 与 `packId: null` 等价，落盘时不留冗余键。

保存后插件会显式重新施加一次：策略写入不产生宿主事件，这是「同一会话内改策略立刻生效」的唯一来源。施加失败只降级，不会让写成功的保存报错。

## 已知边界

- **段归属靠静态扫描**。宿主不记录段或工具的来源，本插件扫各包源码里 `defineTool({ name: '…' })` 与 `.section({ name: '…' })` 的字面量。动态拼出来的名字认不出，就留在孤儿里。
- **认不出的一律不动**。孤儿段照常进 system prompt、孤儿工具照常可用，任何开关都管不到它。宁可少省几百 token，也不误删别人的段——删错一个 1300 字符的段等于废掉一个插件的能力，而且没有兜底。
- **fail-open**。目录读不到、策略读不到、工具清单读不到、waterfall 订阅不上——任一环节失败都按「本轮不改变限制」处理，只 warn。多省几百 token 远不如把模型弄瘫严重。
- **不卸载进程**。停用只影响模型侧：插件照样加载、它的 UI 面板与命令照样在、别的 agent 的作用域不受影响。真正的启停是 profile 的 bundle 开关，是另一件事。
- **只收紧，不放宽**。工具那条通道是 deny 掩码，取交集。别的插件已经 deny 的工具，这里无法放回来。
- **`run_code` 进不了掩码**。宿主把它保留给 PTC transport，写进去会整批拒绝，所以它被跳过。
- **官方插件可能识别不到**。官方包打在 `app.asar` 里，不在 profile 的 `node_modules` 下，得单独从归档头里读；定位失败时列表只剩第三方插件，面板给黄条明说。
- **旧宿主**。没有 `tools.restrict()` 或没有 `system-prompt/assemble` 时插件照常加载、配置照常保存，只降级成单通道并标红。不退回遮蔽注册：同一功能两套实现会带来两套 bug。
- 会话中途切换工作目录不会重算策略，重开会话即恢复。
- 体积是估算：`toolVolume` 按 schema 投影字符数除以 4，段按字符数除以 4，不是账单。
