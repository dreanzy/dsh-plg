# 编辑与提交重新分开：预览改由服务端试算

## 背景与决定

[0005](./0005-draft-and-save.md) 曾把「编辑」与「提交」分开，后来废弃了。它放弃的理由写在最后一条后果里：

> 预览必须在客户端重算一遍求值链（并带上草稿），否则打开一个分组后组内成员仍显示服务端的旧值，看起来就像开关没生效。

那条代价现在没有了：`apply` 接受 `dryRun: true`，在同一套服务端应用规则上算出**不落盘**的视图。浏览器因此不必再复制求值链，面板拿到的待确认视图与真写后的视图出自同一条路径。

跨包的决定见 [根 ADR 0006](../../../docs/adr/0006-pending-changes-before-commit.md)。本文只记本包落地的两处取舍。

## 本包的具体做法

- 点控件 → 入队 → `dryRun` 试算 → 面板按试算视图渲染；「保存」把整批命令作为一次 `apply` 写盘。
- 队列按目标键去重（项级、组级、绑定、归属、改名、手动路径），新建类命令不去重。
- 待保存期间冻结排序：分包页的 rank 与分组页的名字序都取改动前的那份视图。归属变化不冻结，那是用户动作本身的后果。
- 删除（`deletePack` / `deleteGroup`）不进队列、当场写盘。删之前先把队列里引用该对象的命令剔掉，并在面板上说明丢了几项——否则它们会在保存时报错。
- 分组增删改在 0005 里是例外（保持即时写入），本包改为：新建与改名入队，删除仍即时。理由是删除同时清掉所有 pack 里的组级开关，撤销无从谈起；而新建与改名是可逆的。
- 「工作区」页不再提供手动添加/移除目录，`addExtra` / `removeExtra` 两条命令与数据字段 `extra` 一并删掉：目录从哪来回宿主管，本插件只决定「目录 → pack」。旧 `workspaces.json` 里的 `extra` 读取时忽略、下次写盘自然消失，不做迁移。
- 新建分组与新建 pack 在客户端先查重名，并在服务端也拒。只靠服务端拒的话，失败会让整份 `groups.json` 这次不应用，界面上表现为「点了新建、什么都没出现」。

## 考虑过的替代方案

- **沿用 0005 的客户端草稿 + 客户端重算**：求值链现在有四环（项级、组级、默认项级、默认组级），复制一份必然与 `effective.ts` 漂移。否。
- **拖拽排序**：排序是派生的（按状态档位与名字），没有可写的顺序，拖拽只会制造一个不存在的概念。否。
