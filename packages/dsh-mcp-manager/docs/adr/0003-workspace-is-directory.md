# 0003 工作区是目录，四个字段各自求值

## 背景与决定

两件事一起定：

1. **工作区身份**：沿用 `dsh-skill-manager` 的定义——一个目录路径，策略放 `<cwd>/.dsh/mcp-manager.json`，与 `skill-manager.json` 同目录。不用 `workspaceRegistry` 的持久化记录。
2. **求值粒度**：一行的四件事（允许、模式、工具规则、描述）**各自独立**走「工作区 → 全局 → 默认」，而不是「整行取最具体的那一层」。

## 考虑过的替代方案

- **按 workspace id 存**：能跟随工作区重命名，但要处理记录被删、目录改名、记录与目录脱钩三类边角，对「这个工程要不要用这台 server」没有额外收益。
- **整行取最具体层**：实现更简单，但表达不出「工作区只把这行关掉、模式仍沿用全局设置」这种最常见组合——整行取最具体层会强迫用户在关它的同时把模式也抄一遍。
- **工作区层单独存一份完整策略**：等于复制，两份一旦不同步就没人说得清哪份生效。

## 后果

- 策略文件是工程约定，可提交、可共享；插件不碰 `.gitignore`。
- 同一目录被两个 workspace 打开时共享同一份策略，这是预期行为。
- 目录搬家会丢工作区层配置，接受。
- 面板必须能标出每个字段「来自哪一层」，否则用户改不动看不见生效的东西。
- 会话中途换目录会重算该会话的策略——这是 `dsh-skill-manager` 那条已知限制没有做的事，MCP 这边因为注册都落在 per-agent scope 且 dispose 精确，做得到。
