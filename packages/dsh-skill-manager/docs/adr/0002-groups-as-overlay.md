# 分组是策略的一层，不是批量写入的快捷方式

## 背景与决定

需求是「开关一个分组，批量改变组内 skill 的可见性」。两种实现都能满足字面要求，但语义不同：把组开关展开成组内 N 条项级决定（快捷方式），或让组自己在每一层成为一条独立的键（覆盖层）。

选覆盖层。求值链固定为：

```
工作区项级 ?? 工作区组级 ?? 全局项级 ?? 全局组级 ?? 默认开
```

两个要点：一是组内后加入的成员自动跟随该组已有的决定，快捷方式做不到；二是**层优先**——工作区的任何决定（无论项级还是组级）都压过全局的任何决定。若让全局项级压过工作区组级，就会出现「在工作区点了开、界面显示开、模型看不见」的状态，这是最难排查的一类故障。

组定义（id、名字、成员）与开关决定分开存放：定义在全局的 `groups.json`，跨工作区共享；决定在各自的层里，只记 id。重命名组因此不需要扫任何工程文件。

## 考虑过的替代方案

- **组＝批量展开**：实现最简、求值层不变，但组内成员变化不自动跟随，「组开关」的状态只能从 N 条项反推，必然出现莫名其妙的混合态。
- **项级决定一律压过组级（跨层）**：会把全局某个旧决定变成工作区的隐形否决者，见上。

## 后果

- 组开关是三态（跟随 / 开 / 关），只显示组级值，不被项级覆盖污染。
- 项级相对组级必须能显式回到「跟随」，即每行一个 ↺，只在该行有覆盖时出现。用「拨回与上层同值即删键」是行不通的：用户可能先显式打开一项，再把整个组关掉，指望这项仍开着。
- 一个项最多属于一个组；未分组是缺省归属，不是可开关的组。
- 删除组后，各层残留的组决定保留不清理，面板标为失效组，组重建即恢复语义。
